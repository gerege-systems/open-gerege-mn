# Gerege Template Platform V3.0 — Desktop-приложение (TemplateDesktop)

> 🌐 [Монгол](README.md) · [中文](README_ZH.md) · **Русский**

> **Основа для создания электронных услуг** — _Одна платформа — все услуги государства и частного сектора._

**Desktop-клиент** платформы **Gerege Template Platform V3.0**. Это оболочка на
Electron: она загружает веб-интерфейс платформы **один в один** и добавляет
поверх браузера нативное окно, меню, горячие клавиши и политику разрешений.

> **Ничего не переписано:** страницы, сценарии, дизайн, i18n, BFF — всё это тот
> же код из `frontend/`. У desktop-слоя нет собственного UI, поэтому изменения
> в вебе появляются в приложении **без пересборки**.

Поддерживаемая платформа сейчас — **macOS 12+**. Базовая конфигурация для
Windows/Linux заготовлена в `electron-builder.yml`, но не проверялась.

## Архитектура

```
┌────────────────────────────┐
│  TemplateDesktop (Electron)│  окно · меню · политика навигации · разрешения
│  ┌──────────────────────┐  │
│  │ Chromium BrowserWindow│ │  →  https://template.gerege.mn  (Next.js BFF)
│  └──────────────────────┘  │           │
└────────────────────────────┘           └→  Go API (/api/v1/*) — напрямую не вызывается
```

- Приложение **не обращается к backend напрямую** — все запросы идут через BFF
  веб-приложения.
- Сессия хранится в **httpOnly cookie** (`dgov_access` / `dgov_refresh`).
  Хранилище cookie Chromium лежит в `userData`, поэтому после перезапуска
  пользователь остаётся авторизованным.
- CSRF, проверка Origin, CSP — всё остаётся на стороне веба. Desktop не держит
  токенов и не отдаёт их в JS.

### Preload окна

Preload устанавливает один из двух мостов — в зависимости от схемы страницы:

| Страница | Схема | Мост | Возможности |
|---|---|---|---|
| Веб-приложение | `https:` | `window.geregeDesktop` | только метка для чтения (`isDesktop`, `platform`, `appVersion`, `overlayTitleBar`, `titleBarInset`) |
| Внутренняя страница | `file:` | `window.geregeShell` | смена сервера, перезагрузка, закрытие окна |

Удалённый контент **никогда** не получает доступ к IPC оболочки. Главный процесс
дополнительно проверяет каждый IPC по адресу отправителя `file://`
(`src/main.ts` → `fromInternalPage`).

### Политика навигации (`src/policy.ts`)

| Адрес | Действие |
|---|---|
| Собственный origin приложения | открывается в окне |
| `*.gerege.mn`, `eidmongolia.mn`, `accounts.google.com`, `*.dropbox.com` | открывается в окне — OAuth-callback должен вернуться в cookie-хранилище приложения |
| Прочие `http(s)` (документация, GitHub, dgov.mn) | системный браузер |
| `mailto:`, `geregesmartid://` и т. п. | операционная система |
| `javascript:`, `data:`, `blob:` чужого origin | полностью блокируются |

`<webview>` запрещён, доступ к устройствам (HID/Serial/USB) закрыт. Из
браузерных разрешений открыты только **микрофон** (AI-чат · голосовые
сообщения · синхронный перевод), уведомления и полноэкранный режим — камера и
геолокация закрыты.

Из User-Agent удаляется метка `Electron/…`: сервисы вроде Google и Dropbox
отклоняют вход с таким агентом. Реальная версия Chromium сохраняется.

## Desktop-вид

Веб-приложение остаётся **тем же кодом** — но в desktop-окне нет вкладок и
адресной строки браузера, зато есть элементы управления окном. Поэтому вместо
второго UI добавлен один слой стилей:

```
preload  →  window.geregeDesktop { isDesktop, platform, overlayTitleBar, titleBarInset }
              ↓  (theme-bootstrap.js — ДО гидратации)
<html data-desktop="darwin" data-titlebar="overlay" style="--titlebar-inset: 78px">
              ↓
frontend/src/app/globals.css → html[data-desktop] { … }
```

Метку ставит блокирующий `public/theme-bootstrap.js`, поэтому desktop-вид
действует **с первой отрисовки** — вёрстка не мигает.

| Что меняется | Зачем |
|---|---|
| На macOS заголовок окна встроен в окно (`hiddenInset`) | Верхний ряд приложения (icon rail · шапка sidepanel · `topbar2`) сам работает как заголовок — не появляется лишняя полоса в 64px |
| Весь верхний ряд — **зона перетаскивания** | Окно можно двигать откуда угодно. Кнопки/поиск/меню помечены `no-drag` и нажимаются как обычно |
| Слева вверху резервируется `--titlebar-inset` (78px) | Кнопки светофора не перекрывают контент |
| Текст меню и панелей не выделяется | В нативном окне chrome — не текст; подсветка при перетаскивании выглядит дефектом |
| Тонкий скроллбар, отключён rubber-band | Ближе к нативному ощущению macOS |

Кнопки светофора располагаются в шапке icon rail, поэтому **маленький знак
бренда там скрыт** (название бренда осталось в шапке sidepanel). В полноэкранном
режиме кнопки исчезают, а DOM об этом не знает — оболочка сама обнуляет
зарезервированный отступ через `webContents.insertCSS` (`src/windows.ts`).

На Windows/Linux окно остаётся со **стандартной рамкой** (`data-titlebar` не
ставится) — эти платформы в репозитории не проверены, поэтому рисовать элементы
управления окном самим было бы риском. Метка `data-desktop` ставится везде.

## Автообновление

Приложение **само** находит новую версию, скачивает её и перезапускается —
пользователю не нужно ничего качать вручную. Основа —
[`electron-updater`](https://www.electron.build/auto-update).

```
через 30 сек после старта → далее каждые 6 часов → читает latest-mac.yml
        ↓ действительно ли версия новее (проверка semver — старый пакет не скачается)
    фоновая загрузка (в подписи пункта меню виден процент)
        ↓ по завершении
   «Перезапустить сейчас» / «Позже»
        ↓                        ↓
   ставится и возвращается   установится при выходе из приложения
```

**Почему спрашиваем:** в момент завершения загрузки пользователь может заполнять
форму или общаться с AI — тихо закрыть приложение значит потерять данные. Кнопка
по умолчанию — «Перезапустить сейчас»; если отложить, `autoInstallOnAppQuit`
установит обновление при следующем выходе. Ручная загрузка не нужна ни в одном
из случаев.

Пункт меню **«Проверить обновления…»** (macOS: меню приложения, остальные:
Справка) сам сообщает состояние — `Шинэчлэлт татаж байна… 42%`,
`Шинэчлэлт бэлэн (1.1.0) — дахин эхлүүлэх`. Сообщения «обновлений нет» и об
ошибках показываются только при ручной проверке; автоматическая работает молча.

| Настройка | Значение |
|---|---|
| Канал | `https://template.gerege.mn/desktop/updates/` (`src/config.ts` и `electron-builder.yml` — **должны совпадать**) |
| `GEREGE_UPDATE_URL` | временно сменить канал (проверка staging). Только **https** (на loopback допустим http); при неверном значении — возврат к каналу по умолчанию |
| `GEREGE_UPDATE_DEV=1` | принудительная проверка в неупакованном режиме (нужен `dev-app-update.yml`) |

Смены канала из интерфейса **намеренно нет** — сменить канал равносильно замене
кода.

### Выпуск новой версии

```bash
# 1. Поднять version в package.json (semver)
npm version patch --no-git-tag-version

# 2. Подписанная сборка (для автообновления подпись ОБЯЗАТЕЛЬНА)
npm run dist:mac:signed

# 3. Выложить артефакты из release/ в каталог канала
#    Gerege Template-<v>-arm64-mac.zip        ← Squirrel.Mac ставит только из zip
#    Gerege Template-<v>-arm64-mac.zip.blockmap
#    Gerege Template-<v>-x64-mac.zip (+ blockmap)
#    latest-mac.yml                            ← указатель канала — выкладывать ПОСЛЕДНИМ
#    (dmg — только для первой ручной установки, в обновлении не участвует)
```

Выложить `latest-mac.yml` последним важно: если указатель обновится раньше, чем
догрузится пакет, приложение попытается скачать несуществующий файл и выдаст
ошибку.

> ⚠️ **На неподписанной сборке автообновление не работает.** Squirrel.Mac
> сверяет подпись скачанного пакета с установленным приложением и при
> несовпадении отказывается ставить. Локальная сборка (`npm run dist:mac`)
> сможет проверить и скачать обновление, но упадёт на шаге установки.

## Разработка

```bash
cd desktop/TemplateDesktop
npm install

npm start        # рабочий сервер (template.gerege.mn)
npm run dev      # локальный frontend (localhost:3000) + DevTools
npm test         # тесты политики навигации и разрешений (node --test)
npm run typecheck
```

Перед `npm run dev` запустите в другом терминале `cd frontend && npm run dev`.

### Выбор сервера

Приоритет: переменная окружения `GEREGE_APP_URL` → сохранённый выбор →
`template.gerege.mn`.

Пункт меню **Сменить сервер…** (`⌘⇧S`) — готовые варианты или свой адрес.
Выбор сохраняется в `userData/state.json`. Если задан `GEREGE_APP_URL`, при
следующем запуске будет использован именно он (в окне выводится предупреждение).

## Сборка

```bash
npm run icon           # frontend/public/brand.webp → resources/icon.icns
npm run dist:mac       # release/*.dmg + *.zip (arm64 · x64), без подписи
```

Неподписанная сборка предназначена **только для локальной проверки** — Gatekeeper
сообщит, что приложение «повреждено»
(`xattr -dr com.apple.quarantine "/Applications/Gerege Template.app"`
или Системные настройки → Конфиденциальность и безопасность → «Всё равно открыть»).

Для распространения нужен Apple Developer ID:

```bash
export CSC_LINK=... CSC_KEY_PASSWORD=...          # сертификат Developer ID Application
export APPLE_ID=... APPLE_APP_SPECIFIC_PASSWORD=... APPLE_TEAM_ID=...
npm run dist:mac:signed                            # подпись + нотаризация
```

Hardened runtime, entitlements (`build/entitlements.mac.plist`) и
`NSMicrophoneUsageDescription` уже настроены.

## Структура файлов

```
src/
  main.ts        точка входа — session, разрешения, IPC, жизненный цикл
  windows.ts     создание окон, сохранение геометрии, привязка политики
  menu.ts        системное меню (на монгольском)
  policy.ts      чистые решения — classifyURL, allowPermission, очистка UA
  update.ts      чистые решения — сравнение semver, частота проверок, подписи меню
  updater.ts     поток автообновления (electron-updater, диалоги, перезапуск)
  config.ts      базовые адреса, белый список, канал обновлений, нормализация адреса
  store.ts       userData/state.json (геометрия окна, сервер, время последней проверки)
  preload.ts     два моста в зависимости от схемы
  policy.test.ts тесты политики
  update.test.ts тесты решений об обновлении
static/          внутренние страницы — offline.html, server.html, shell.css
build/           entitlements
resources/       icon.icns
scripts/         make-icon.sh
```

## Ограничения и примечания

- **Нужен интернет** — офлайн-режима нет. Если сервер недоступен, показывается
  внутренняя офлайн-страница с кнопкой «Повторить» (при восстановлении сети
  повтор происходит автоматически).
- **Автообновление касается только оболочки.** Веб-контент всегда актуален,
  поэтому новая версия выходит лишь при изменении оболочки (окно, меню,
  политики). На неподписанной сборке шаг установки не сработает (см. выше).
- **Desktop-вид — это только слой стилей.** Страницы и потоки остаются 1:1 с
  вебом; desktop лишь настраивает chrome через `html[data-desktop]`.
- `geregetemp://eid/callback` (мост App2App для iOS) на desktop не
  зарегистрирован — здесь поток eID идёт через `/auth/eid/callback`.
- `npm audit` предупреждает о транзитивных зависимостях `electron-builder`.
  Это инструменты **только времени сборки**, в пакет они не попадают;
  исправление требует несовместимого понижения electron-builder, поэтому
  отложено.
